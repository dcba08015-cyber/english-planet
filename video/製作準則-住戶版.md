# 住戶版影片製作準則

> 老闆回饋：「太本位主義了，還是用工程師角度在設計。要用一般使用者、
> 看完長輩都看得懂的角度。」——這份準則就是為了回應這件事。

## 核心差異

| | ❌ 工程師版（EP01 舊版） | ✅ 住戶版（EP01 新版） |
|---|---|---|
| 在教什麼 | 教你怎麼**診斷** | 教你**照著做** |
| 畫面 | 黑底綠字終端機 | 明亮底、實物圖、大字 |
| 動作 | 打指令 `ping 192.168.1.1` | 看燈、拔插頭、數數、等 |
| 用詞 | DNS、TTL、封包、L1/L2 | 完全不出現 |
| 東西怎麼叫 | 「分享器」「數據機」 | 「牆邊那台一直閃燈的機器」 |
| 結尾 | 下集預告 | **大字電話號碼** |

## 六條規則

1. **畫面只出現使用者真的看得到的東西**
   手機截圖、設備外觀、燈號顏色。**不准有終端機、不准有程式碼。**

2. **不出現任何指令**
   只有「按這裡」「拔這條」「等一下」。使用者手上只有手機，做不到的事不要教。

3. **一支影片只教一個動作**
   不做分支判斷。判斷交給 LINE 的 AI 去問，影片只負責「這一步怎麼做」。

4. **東西用長相叫，不用型號叫**
   ❌ 數據機／ONU／分享器
   ✅ 牆邊那台一直閃燈的白色機器

5. **字要大、要慢**
   字幕 60px 起跳，每個步驟停留 3 秒以上。長輩需要時間讀完再抬頭看畫面。

6. **結尾一定要有「還是不行怎麼辦」**
   大字電話號碼 + App 報修。沒有這個，長輩不敢動手——他們怕弄壞東西要賠。

## 驗收標準

**拿給家裡 60 歲以上的長輩看，不解釋、不補充，看他能不能自己做完。**

做不完就是我們的問題，不是他的問題。

檢查三件事：
- 他有沒有中途問「這是什麼意思」→ 有術語沒清乾淨
- 他有沒有暫停倒回去看 → 節奏太快或字太小
- 他做完之後敢不敢動手 → 缺「還是不行怎麼辦」的安心感

## 檔案

| 檔案 | 版本 |
|---|---|
| `scene.html` + `timeline.js` | 工程師版（保留，網路排錯教學頻道還用得到） |
| `scene-v2.html` + `timeline-v2.js` | **住戶版，客服素材一律用這個** |
| `render-v2.mjs` | 住戶版渲染器 |

## 住戶版的四段結構

```
鉤子    用「症狀」開場，不用「解法」開場
        ✅「Wi-Fi 有連上，網頁卻打不開？」
        ❌「三行指令抓出兇手」← 這是恐嚇

第一步  先做「不用動手」的判斷（看燈、看畫面）
        並在這裡就給出「這不是你的問題」的岔路

第二步  實體動作（拔插頭、重開、換位置）
        長輩做實體動作比做手機操作穩

第三步  等待 + 驗證（等燈亮、再試一次）
        一定要講「要等多久」，不然他會以為壞了

收尾    大字電話 + App 報修
```
